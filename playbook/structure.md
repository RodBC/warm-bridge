# Approach structure (stable skeleton)

All approach drafts share one skeleton. Bridge type changes *mode and wording*, not the shape.

## Message shape (fixed order)

1. **Greeting** — first name only when known  
2. **Context line** — why you’re writing (1 sentence)  
3. **Target line** — who you want to reach + role/company  
4. **Ask** — one clear ask matching mode  
5. **Forwardable blurb** (optional, for `ask_intro` / `peer_forward`) — 2–3 lines the bridge can paste  
6. **Out** — easy decline  

## Modes

| Mode | When | Ask |
|------|------|-----|
| `ask_intro` | `high` strength + strong bridge type | Warm intro to target |
| `peer_forward` | Medium strength, bridge can forward | “Pode encaminhar este texto?” |
| `ask_intel` | Weak/medium, need map of org | “Quem decide X aí?” / context |
| `ask_permission` | Soft tie (`alumni`, stale) | OK to mention name / soft open |

## Channel packs

| Locale | Default channel vibe |
|--------|----------------------|
| `pt` | WhatsApp / ligação — curto, oral |
| `en` | LinkedIn DM / email — still short |

## Budget

| Part | Limit |
|------|-------|
| Full message | ~80–120 words before signature |
| Forwardable blurb | ≤ 3 short lines |
| Product claims | 0–1 concrete outcome max; no feature dump |

## What changes per bridge (only)

| Field | Changes? |
|-------|----------|
| Seller identity | No |
| Target name/company | No (input) |
| Bridge name / company / notes used as facts | No inventing |
| Mode | Yes |
| Wording / CTA | Yes |
| Whether blurb is included | Yes |
